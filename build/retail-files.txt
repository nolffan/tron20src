## The retail game the build takes its data from: Tron 2.0 (USA), as its
## own setup installs it from its two discs ("Recommended"), with Update 2
## (v1.030, the "complete" update) installed over it. This list holds no
## game data. It tells build/discs.py which bytes of which disc, cabinet or
## update make each file, and what each file must be (its size and SHA-256).
## The update's files ("update" rows) are only the reference of the checks
## (make progress, make art-check, build/assets.py): the game directory and
## the install scripts take only the discs' files, and Update 2's data
## ships in assets/ (assets/README.md).
##
## D <disc> <volume label> <volume blocks> <image size> <image SHA-256> <image name>
##   One disc. A disc image is recognised by its volume label and its volume
##   size (blocks of 2048 bytes). The image size, SHA-256 and name are those
##   of one known good image (the .iso of the redump dump). Another correct
##   copy of the disc can have another size and SHA-256: each file is checked.
## U <name> <size> <SHA-256>
##   The update's executable, recognised by its size and SHA-256.
## C <name> <size> <SHA-256> <disc> <offset> <path on the disc>
##   One file of the discs' InstallShield cabinet set: its name in the work
##   directory, its size and SHA-256, and where it is: the byte offset of
##   its data in the disc's 2048-byte-sector image, and its path in the
##   disc's file system.
## F <path> <size> <SHA-256> <source> <where> <name>
##   One installed file: its path in the install, its size and SHA-256, and
##   where it is. With a disc number as the source: <where> is the byte
##   offset of its data on that disc, <name> its path on the disc. With
##   "cab" (the discs' cabinets) or "update" (the update's cabinets):
##   <where> is the InstallShield file group, <name> its path in the group.
## The fields are separated by one TAB.
